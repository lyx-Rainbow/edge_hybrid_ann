### 5 查询 Profiling 分解

| 阶段 | sift1m | gist1m | yfcc100m | arxiv | wit |
|------|:---:|:---:|:---:|:---:|:---:|
| Beam Search | 0.065 ms | 0.169 ms | 0.102 ms | 0.127 ms | 0.119 ms |
| PQ Table Build | 0.021 ms | 0.074 ms | 0.046 ms | 0.091 ms | 0.075 ms |
| **PQ Distance Compute** | **0.645 ms** | **0.563 ms** | **1.181 ms** | **110.976 ms** | **419.678 ms** |
| Candidate Merge | 0.168 ms | 0.091 ms | 0.084 ms | 0.318 ms | 0.204 ms |
| Frontier Overhead | 0.168 ms | 0.122 ms | 0.030 ms | 0.028 ms | 0.241 ms |
| ADC Rerank | 0.049 ms | 0.090 ms | 0.063 ms | 0.060 ms | 0.080 ms |
| **I/O 时间开销** | 0.031 ms | 0.063 ms | 0.045 ms | 67.253 ms | 129.537 ms |
| **I/O 次数** | 35,356F / 245P | 38,041F / 245P | 19,084F / 196P | 18,705F / 701,863P | 34,946F / 2,689,432P |
| **总计** | **1.136 ms** | **1.134 ms** | **1.677 ms** | **111.820 ms** | **421.806 ms** |

> **I/O 指标说明**: "I/O 时间开销" = (Flash I/O + PQ I/O) / 查询数，即单条查询平摊的磁盘 I/O 耗时。"I/O 次数" 中 F=Flash Store 读取次数，P=PQ Block Cache 磁盘读取次数（不含缓存命中）。两指标共同反映磁盘 I/O 对查询延迟的贡献——小数据集（sift/gist/yfcc）I/O 极低（<0.07ms/query），大数据集（arxiv/wit）I/O 成为延迟主导因素（58%+）。
